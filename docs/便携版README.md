# 报销单据智能校验智能体

用于 Windows 单机演示的报销财务预审工具：本地识别 PDF / PNG / JPG，按确定性规则核对金额、抬头、税号、日期与附件，导出可追溯的中文 PDF。采用“导入材料 → 确认信息 → 查看审核 → 导出报告”四步界面，支持自定义模型接口。交付包含内置运行环境的 Windows 便携版及比赛源码；外部模型需使用自己的服务配置验证。

## 给使用者：三步体验

1. 在 **Windows 10/11 64 位** 上完整解压 **报销审核_开箱即用.zip**，进入 **报销审核智能体** 文件夹，双击 **报销审核智能体.exe**。便携版已内置 Python 运行库、桌面组件、依赖、OCR 模型与中文字体，**无需自行安装 Python 或依赖**；本地审核可离线运行，不要求独立显卡。不要只复制 exe，须保留同级 **_internal** 文件夹。
2. 在主页 **两张卡片下方** 点击 **「没有现成材料？载入 10 笔演示样例」**，一步载入并识别 10 笔原票（与赛题样例一致）；也可以先点 **新建报销 → 开始**，在 **导入材料** 页点击 **载入演示**，效果相同。等待识别完成后进入 **确认信息**，点击底部 **开始审核**；在 **查看审核** 点击 **审核全部任务** 可审核其余报销。默认只显示问题，勾选 **显示全部校验项** 查看完整检查。
3. 进入 **导出报告**，点击 **合并导出全部任务**，选择保存位置，得到一个含全部报销的中文 PDF。单笔报告使用底部 **导出 PDF**；**查看执行记录** 可展开业务工具日志。

首次使用可先阅读同目录的 **便携版使用说明.md**；详细操作见 **使用手册.html**，均可离线阅读。包内 **源码/报销审核_比赛源码.zip** 用于平台源码提交和开发复现，其运行方式与便携版不同。

2026-10-26 的便携版通过 **24 项业务及 23 项界面检查**（界面检查含“首屏演示入口可见”“接入方式胶囊固定在窗口内”“校验能手悬浮球与对话窗”），源码回归 **157/157 通过**。模型接入分**纯规则引擎、本地模型（本机 Ollama）、在线模型（外部接口）**三种，顶部胶囊常驻显示当前方式并可点击切换；桌面悬浮的**校验能手**可直接询问制度与报销原则；本机 `qwen2.5:7b` 与 `qwen2.5:1.5b` 已实测完成真实审核，结论仍由本地规则给出。在线模型只用 loopback 模拟接口验证请求与回退，不等于真实云端联调。详细记录见 **验收结果摘要.md**。这是同一台电脑上的独立路径验证，尚未进行全新虚拟机或第二台实体电脑测试。本次交付目录 **报销审核智能体** 与压缩包 **报销审核_开箱即用.zip** 使用相同内容与目录结构。

主页只保留两张任务入口卡片：**新建报销 → 开始**；**继续处理报销** 在没有当前任务时提供 **打开** 项目，有当前任务时提供 **继续** 及 **打开其他项目**。卡片下方另有一行文字入口 **「没有现成材料？载入 10 笔演示样例」**：10 笔样例是本题的验收场景，原来只能进任务后在 **导入材料** 里找，首屏看不到等于把最该演示的路径藏起来了。主页不显示任务表与业务导航。进入工作区后，顶部显示 **主页、新建报销、打开项目、保存项目、审核规则、高级设置** 六项导航，左侧显示报销任务列表。点击 **主页** 返回入口，继续后保留原任务、操作步骤与字段修改；关闭前仍需点击 **保存项目** 将进度保存到文件。**预览原图** 按钮位于 **导入材料** 和 **确认信息**。

界面统一采用 **银灰背景、白色卡片与苹果蓝点缀**，放大的入口按钮和顶部玻璃导航带便于操作，导航带通过高光边缘与柔和阴影分隔内容区。轻微入场、悬停及步骤过渡衔接组件；系统关闭动画或使用键盘操作时直接切换，业务操作立即执行。内容较多时可在表单区域滚动；原图窗口支持缩放与翻页。

原始演示只有发票，缺少报销申请及付款凭证；日期按原票开票日期和演示提交日期重新计算。**审核规则里备了两套一键口径**，只改「期限」与「必需附件」，校验逻辑一行未改：

| 口径 | 期限 | 必需附件 | 10 笔结果 |
| --- | --- | --- | --- |
| 严格口径（默认） | 90 天 | 发票、报销申请、付款凭证 | 全部不通过：缺附件，且首笔开票距提交 156 天 |
| 演示口径 | 180 天 | 发票 | 2 通过 / 8 不通过，与赛题参考结果单逐笔一致 |

参考结果单把首笔的 156 天标成「通过」，却写着「不超过 90 天」，自相矛盾。严格口径按要求实算并给出计算过程；要与参考单对齐时切演示口径即可。报告第一节始终打印本次口径、期限、必需附件与口径说明，切换不会被隐藏。

## 新建与继续编辑

- 在主页点击 **新建报销 → 开始**，或在工作区顶部点击 **新建报销**，于 **导入材料** 填写申请人、部门、提交日期（YYYY-MM-DD）及申请金额，再点击 **普通导入** 一次选择多张发票和附件，均归入当前一笔报销。普通导入仅在本地识别，不调用在线模型。识别完成后保持在当前页，可继续分批添加；材料齐全后再点击 **下一步：确认信息**。**提交日期默认取今天**，这只是新建单据的日期：今天新建、今天提交是正常流程；若是在补录几年前的票据，请把提交日期改成实际提交日期，或导入报销申请单让程序自动读取，否则所有票据都会按「超过报销期限」判不通过——那是正确判定，不是识别错误。
- 在文件列表确认 **材料类别**。自动分类不确定时，人工选择“发票 / 报销申请 / 付款凭证 / 其他”；选中文件点击 **预览原图**（或双击文件行）可在程序内查看图片或 PDF，支持缩放、拖动和翻页。**外部打开** 使用系统阅读器。
- 陌生版式未提取出发票时，将 **材料类别** 改为“发票”，即可在 **确认信息** 手工补录。补录后需对照原件明确核对全部字段和明细；损坏文件仍须重新导入。
- 进入 **确认信息**，从下拉框逐张查看，点击 **预览原图** 即可打开该张发票对应的原文件和页码；**查看原文与依据** 展示识别文字和字段来源。修改后点击 **保存字段与核对记录**，再使用底部 **开始审核**。
- 明细采用中文表格，通过“项目明细”旁的 **添加 / 编辑 / 删除** 补正名称、数量、单价、金额、税率与税额。请先对照原票逐页核对，再勾选 **我已对照原票，核对本票全部页面与明细**；仅保存字段不代表已经核对遗漏的页和明细。
- 修改信息、字段、附件或规则后，需重新审核，之后才能导出 PDF。
- **保存项目** 会保存申请、提取值、修改记录和规则。**原单据继续使用原路径，不会自动复制进项目文件**，迁移电脑时请保留原文件并重新导入。打开项目会替换当前列表，先保存当前工作。

## 看见 AI 工作：一键导入

1. 在 **高级设置** 填写接口地址、模型名称及对应密钥，点击 **完成**。随后在 **导入材料** 点击主按钮 **AI 一键导入**，选择新的图片或 PDF：程序先本地 OCR，再为每份文件真实调用一次当前所选模型整理字段。此按钮不依赖“启用模型辅助审核”勾选，该选项只控制后续审核阶段。
2. 留在当前页观察 AI 工作台的实际处理阶段和结果。工作台列出 **字段原值、AI 建议、原文证据、处理状态**；选择文件行可切换该文件的结果，选择一条建议可查看依据。
3. 已通过普通导入添加的材料，使用 **AI 整理已有材料**，不会重复 OCR 或添加文件。核对建议后再进入 **确认信息**。

AI 只补充空白且未经人工确认的字段，补入后仍标为待确认；已有值与人工确认内容会保留，差异标为待复核，无原文依据的建议会被拒绝。当前功能只整理本地已经识别出的发票页字段，不会自动新建陌生版式发票，也不会代填申请人、部门、提交日期或申请金额，不会自动给出审核通过结论。调用失败时保留本地识别结果，可继续人工核对。

## 规则与结果

默认演示抬头为“北京蓝海智能科技有限公司”，税号为 `91110108MA01XYZ7K9`；期限 90 天；必需附件为发票、报销申请、付款凭证。可在顶部导航栏 **审核规则** 修改。金额使用 Decimal 按分核对，税额容差为 ±0.01 元。

检查结果包括“通过、不通过、待人工复核、不适用”；整笔存在确定违规则“不通过”，没有确定违规但有不确定项则“待人工复核”，必需检查完成后才可“预审通过”。报告保留实际值、期望值、原因、来源页码及人工复核空栏。

本程序执行**财务预审**。未接入税务发票真伪查询，也不代替业务真实性核实、财务审批和签章。陌生版式、扫描不清或明细未完整识别时，请对照原票复核；不要直接确认尚未核对的空字段。

## 模型接入：本地、在线或纯规则

本地 OCR、规则审核、字段修正和 PDF 导出均无需模型。右上角的**接入方式胶囊**始终显示当前选择（`纯规则引擎` / `本地模型 · qwen2.5:7b` / `在线模型 · deepseek-chat`），点击即可切换；切换只影响之后的新审核与 AI 导入，已完成结论保留原记录。报告的“运行模式”也会写明本次使用的接入方式。

**纯规则引擎**：不调用任何模型，不发送任何文字，结论仍完整可信。

**本地模型（Ollama）**：单据识别文字不出本机。

1. 安装并启动 Ollama，拉取一个支持工具调用的模型，例如 `ollama pull qwen2.5:7b` 或 `ollama pull qwen2.5:1.5b`。
2. 点击右上角胶囊，**本机模型**分组会实时列出已安装模型及其参数量与体积，点选即完成接入：地址自动设为 `http://127.0.0.1:11434/v1`，无需密钥。
3. 也可在 **高级设置 → 本机模型（Ollama） → 检测本机模型 → 使用此模型**，检测结果会填入上方地址与模型名。
4. 7B 模型在 CPU 上首次加载需要数十秒；程序对本地服务使用 240 秒超时，对云端服务使用 60 秒超时。
5. 本地路径由程序顺序执行"提取单据 → 规则校验 → 生成摘要"三个工具，模型只做一次问题说明。小参数量模型（1.5B）难以稳定驱动多轮工具调用，这样既快又不会跑偏；说明中的数字若不在工具结果里，整段丢弃。

**在线服务**：任意 OpenAI 兼容 Chat Completions 接口，审核阶段需支持工具调用。

1. 在 **高级设置 → 新增** 填写配置名称、接口地址、模型名称、API 密钥，可保存多套后从“已保存配置”切换。接口地址可填 Base URL 或完整 `/chat/completions` 地址。
2. 点击 **测试连接**。测试只发送一条连接消息，不发送报销材料。
3. 点击 **完成** 后，AI 导入立即使用该配置；审核阶段还需勾选 **启用模型辅助审核**，或直接从右上角胶囊切换。

| 接入示例 | 接口地址 | 模型名称与密钥 |
| --- | --- | --- |
| 本机 Ollama | `http://127.0.0.1:11434/v1` | 胶囊自动列出本机模型；无认证服务密钥留空 |
| 在线兼容服务 | 服务商提供的 Base URL | 填写该服务的模型 ID 与对应密钥 |
| 默认智谱 | `https://open.bigmodel.cn/api/paas/v4` | 默认 `glm-4.7-flash`，可改为账号支持的模型 |

远程携带密钥时须用 HTTPS。点击 AI 导入或整理时，识别文本和字段会发送至所选服务；启用模型辅助审核时，还会发送必要规则和检查结果。本地 OCR 不上传图片，本地模型只在 127.0.0.1 内通信。费用、限额与模型权限以所选服务为准。模型只能提出有原文证据、待人工确认的建议；金额与最终结论来自本地规则；模型返回的自然语言说明会写进报告第五节，并明确标注“只解释、不改判”。

配置保存在 `%APPDATA%\ReimbursementAudit\model_profiles.json`，内容仅为配置名称、地址、模型与选中项。密钥只在本次运行中使用，不写进配置、项目或源码资料包；可用环境变量 `REIMBURSEMENT_BASE_URL`、`REIMBURSEMENT_MODEL`、`REIMBURSEMENT_API_KEY` 提供，环境变量只在首次运行（尚无配置文件）时作为默认值，之后以界面选择为准。程序不自动读取 `.env`。

已实测：DeepSeek `deepseek-chat` / `deepseek-v4-pro` 在在线路径完成三工具流程；本机 `qwen2.5:7b` 走本地确定性管线，单笔约 8 秒，`qwen2.5:1.5b` 约 10 秒。断网、超时或模型不支持工具调用时保留规则结论并降级，不自动切换其他服务。[Ollama 兼容接口说明](https://docs.ollama.com/api/openai-compatibility)

## 校验能手：窗口内悬浮的财税问答

程序窗口右下角常驻一个圆形的**校验能手**悬浮球（蓝色花瓣图标）。点一下展开对话面板，点 `✕` 或按 `Esc` 收起：

- 悬浮球和对话面板都是**主窗口内部的控件**，只在程序窗口内显示，最小化窗口时一起最小化，不会浮到桌面或盖住其他程序。
- 默认落点在右下角"导出 PDF"按钮上方、白色工作卡内部，不挡主操作，也不会出现跨两种底色的白色方块。
- 拖动悬浮球可以在窗口内换位置，位置和显隐状态记在 `%APPDATA%\ReimbursementAudit\assistant.json`，下次启动沿用（按窗口右下角为基准，窗口缩放后位置不变形）。
- 右键悬浮球可"打开对话"或"隐藏"；隐藏后可在 **高级设置 → 校验能手（窗口内悬浮助手）** 重新显示。
- 标题栏标注当前接入方式：`财税助手 · 纯规则引擎` / `财税助手 · 本地模型 · qwen2.5:7b` / `财税助手 · 在线模型 · deepseek-chat`，与主界面右上角胶囊同源。

**为什么"点下去就有答案"**

| 环节 | 耗时 | 说明 |
| --- | --- | --- |
| 本地检索 + 条文渲染 | **约 36 ms**（实测） | 关键词加权检索命中后立刻画出条文气泡 |
| 模型改写同一气泡 | 取决于模型 | 模型回来后原地替换文字，气泡不闪、不重排 |

- 命中条文时先给条文，再让模型改写；模型慢或失败，条文已经在屏幕上，不会有空白等待。
- 没有条文命中时显示三点跳动，等模型回答；未接入模型则直接给通用口径。
- 本地模型首次调用会把权重加载进显存/内存（`qwen2.5:7b` 冷启动约 30 秒），打开面板时会**在后台预热**，并带 `keep_alive` 保持 30 分钟，之后的提问不再重复加载。
- 提问不到 400 字、条文只取 2~3 条、回答限制 300~420 token，本地 7B 的提示词长度压到 900 字以内。
- 同样的问题命中进程内缓存（48 条），二次提问直接返回。

**三种接入方式下的行为**

| 接入方式 | 回答方式 | 数据流向 |
| --- | --- | --- |
| 纯规则引擎 | 直接引用制度条文原文，约 1 毫秒 | 不联网，不发送任何文字 |
| 本地模型（Ollama） | 本机模型把命中的条文改写成自然语言 | 只在本机 `127.0.0.1` 内通信 |
| 在线模型 | 云端模型生成解释 | 只发送问题、制度参数与命中的条文片段，不发送单据原文 |

**能问什么**

- **公司制度（20 条）**：报销时限、发票抬头与税号、发票号码格式、重复报销、必需附件、金额一致性、必填字段、发票类型与税率、差旅交通/住宿/伙食补助、办公用品、业务招待、会议培训、通讯费、审批流程、常见退回原因、不予报销项、付款凭证、系统检查项。
- **财税法规（15 条）**：会计法（凭证真实、伪造凭证的法律责任）、发票管理办法（如实开具、不合规发票可拒收）、会计档案保管期限（30 年/10 年/5 年）、企业所得税税前扣除凭证（28 号公告、白条不能入账）、企业所得税法第八条（相关且合理）、业务招待费 60% 且不超收入 5‰、广告宣传费 15%、职工福利费 14%/工会经费 2%/教育经费 8%、增值税进项抵扣（集体福利、个人消费不得抵扣）、现金管理暂行条例（结算起点 1000 元）、个人所得税与七项专项附加扣除、民法典定金 20% 上限、反不正当竞争法商业贿赂、合同/发票/资金三流一致。

共 35 条，正文在 `data/policy_kb.json`，是纯文本 JSON，可按贵公司制度自行增删改，改完重启即生效（文件按修改时间缓存，无需清缓存）。

输入框上方的快捷标签可直接点选；`Enter` 发送，`Shift+Enter` 换行。

**回答的边界**

- 只解释制度与法规口径，不对具体单据下结论；单据结论仍由规则引擎计算，模型不能改判。
- 问的是报销/财税范围内的冷门问题，会给出"三项底线"（业务真实、凭证合法、时限与权限）和"建议问财务"，不空口敷衍也不编造。
- 与报销无关的问题（如"今天天气"）会说明只答报销制度、发票规则和财税法规，并给出可问的示例。
- 模型回答中出现制度未载明的数字时，气泡末尾提示"回答中出现制度未载明的数字，请以制度原文为准"。
- 模型不可用（未接入、断网、接口报错、超时 22/55 秒）时保留条文并在尾部注明原因，不会空白或卡住。
- 法规条文以现行有效版本摘要为准，正式结论以财务复核和主管税务机关口径为准。

配置项只保存悬浮球位置与显隐，不含任何密钥或业务数据。

## 从源码运行（开发者）

仅需要运行软件时使用便携版 exe。需要修改源码或复现比赛提交时，先解压 **源码/报销审核_比赛源码.zip**，安装 **Python 3.10～3.12 64 位（含 Tcl/Tk、pip；推荐 3.10.11）**，再双击源码目录的 **启动开发预览.cmd**。该入口会创建独立环境并安装锁定依赖；首次安装需要网络。也可在源码目录打开 PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\安装环境.ps1
.\.venv\Scripts\python.exe environment_check.py --output output\环境检查.json
.\.venv\Scripts\python.exe main.py
```

资源要求：保留 `assets/font.ttf`、字体许可证、`assets/ocr` 模型以及 `data` 演示资料。本程序运行时不会静默下载 OCR 模型。依赖安装需要网络，现有依赖和模型齐全后，本地模式可离线使用。

运行检查与验收：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe main.py --self-test output
```

以本次生成的 `output/验收结果.json` 为验收证据，实际通过数量和未验证项见该文件。报告可在 `output` 中查看。测试覆盖规则边界、异常输入、原始样例及补充演示场景，真实在线 API 需另用自己的密钥验证。

比赛提交时运行 `.\.venv\Scripts\python.exe prepare_submission.py`，得到 `output/报销审核_比赛源码.zip`，包含源码、安装启动脚本、锁定依赖、OCR、字体、样例和测试，不包含 `.venv`、运行缓存、输出记录、快捷方式或用户配置。完整复现方法见 **源码提交说明.md**。不要直接上传开发目录内的 `.venv`；它依赖本机 Python 路径。`requirements-build.txt` 与 `build.py` 用于重新构建 Windows 便携版，源码验收无需安装打包依赖。

## 常见问题

- **便携版打不开 / 缺少文件**：先完整解压到可读写目录，保留 exe 同级的 **_internal**；不要在 ZIP 内直接运行。启动错误记录在 exe 同级 `output/启动错误.log`，不可写时回退 `%LOCALAPPDATA%\ReimbursementAudit\logs\启动错误.log`。
- **源码版打不开 / 缺少依赖**：安装含 Tk 的 64 位 Python 3.10～3.12 后，双击 **安装环境.cmd** 检查依赖，保留 assets 和 data 文件夹；首次安装需要网络。
- **源码版提示 onnxruntime 加载失败**：安装脚本会把 `assets/msvc/` 的 VC++ 运行库复制到 `.venv` 的 `onnxruntime/capi/`，一般无需处理；若仍报 `DLL load failed`，安装 Microsoft Visual C++ 2015–2022 x64 运行库后重跑 **安装环境.cmd**。缺 `assets` 或 `assets/msvc` 时请使用完整源码包。
- **识别慢**：首次初始化 OCR 需要时间。图片逐页在 CPU 上处理，等待底部进度指示结束。
- **空字段 / 陌生发票版式**：打开原票核对并补充字段和明细，不能仅凭模型推断填入无证据数据。
- **附件明明存在却说缺失**：在文件列表选中该文件，确认其类别，重新审核。文件损坏时应重新提供可读取的原件。
- **变更规则后看不到原结论 / 无法导出**：旧结论已失效，点击审核后再导出。
- **保存项目后原票打不开**：项目保存路径引用，原文件被移动或删除后应重新导入。
- **报告无法覆盖**：关闭正在打开该 PDF 的阅读器，或选择新文件名；程序禁止用报告覆盖原始单据。
- **模型服务不可用**：检查接口地址、模型 ID、对应密钥、网络及工具调用支持。先测试连接，再实际审核；失败时仍可本地审核，程序不会自动调用其他模型。
- **想确认 AI 是否工作**：在导入页使用 **AI 一键导入** 或 **AI 整理已有材料**，查看工作台阶段、所选文件的字段建议与证据。**普通导入** 不联网；“测试连接”也不会整理报销材料。

第三方组件及许可证见 `THIRD_PARTY_NOTICES.md`，字体许可证随程序提供。
