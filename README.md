# 报销单据智能校验智能体

面向财务预审的 Windows 桌面工具：本地识别 PDF / PNG / JPG 报销材料，按确定性规则核对金额、抬头、税号、日期与附件完整性，导出可追溯的中文 PDF 审核报告。

> 结论由本地规则给出，模型只负责读字与写说明。纯规则模式下不联网、不调用任何大模型。

## 它解决什么

报销初审的重复劳动集中在三件事：把票据上的字段读准、按制度逐项比对、把比对过程留痕。这个工具把三件事串成一条流水线：

- **本地 OCR**：RapidOCR（PP-OCRv6 模型）离线识别，图片不出本机，不需要 GPU
- **确定性规则引擎**：金额用 `Decimal` 按分核对，税额容差 ±0.01 元；规则可切换口径，判定过程逐步可查
- **可追溯报告**：每条结论都带实际值、期望值、原因、来源页码，并预留人工复核签字栏

## 两套审核口径

赛题原始演示只有发票，缺报销申请与付款凭证；且参考结果单把一笔 156 天的单据标为"通过"却写着"不超过 90 天"，自相矛盾。因此内置两套口径，切换只改「期限」与「必需附件」，校验逻辑一行未改：

| 口径 | 期限 | 必需附件 | 10 笔结果 |
| --- | --- | --- | --- |
| 严格口径（默认） | 90 天 | 发票、报销申请、付款凭证 | 全部不通过：缺附件，且首笔开票距提交 156 天 |
| 演示口径 | 180 天 | 发票 | 2 通过 / 8 不通过，与参考结果单一致 |

报告第一节始终打印本次口径、期限、必需附件与口径说明，切换不会被隐藏。

## 三种模型接入

右上角的**接入方式胶囊**常驻显示当前选择，点击即可切换。切换只影响之后的新审核与 AI 导入，已完成结论保留原记录。

| 模式 | 联网 | 说明 |
| --- | --- | --- |
| 纯规则引擎 | 否 | 不调用任何模型，不发送任何文字，结论完整可信 |
| 本地模型（Ollama） | 否 | 单据文字不出本机，地址自动设为 `http://127.0.0.1:11434/v1`，无需密钥 |
| 在线模型 | 是 | 任意 OpenAI 兼容 Chat Completions 接口，审核阶段需支持工具调用 |

模型只能提出**有原文证据、待人工确认**的建议：金额与最终结论来自本地规则，模型返回的自然语言说明写进报告第五节并标注"只解释、不改判"。

## 快速开始（源码运行）

环境：**Windows 10/11 64 位 + Python 3.10～3.12 64 位**（含 Tcl/Tk、pip；推荐 3.10.11，与依赖 wheel 的 CPython 3.10 锁定一致）。不需要 GPU，不需要模型密钥即可完成识别、审核与导出。

```bat
:: 1. 双击 启动开发预览.cmd
::    首次运行会自动建 .venv、从 PyPI 安装锁定依赖、检查资源，然后启动窗口

:: 2. 或手动分步
powershell -NoProfile -ExecutionPolicy Bypass -File .\安装环境.ps1
.\.venv\Scripts\python.exe environment_check.py --output output\环境检查.json
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
.\.venv\Scripts\python.exe main.py --self-test output\验收
```

首次进入后，在主页点击「没有现成材料？载入 10 笔演示样例」，即可一键载入赛题样例走完整个流程。完整操作见 [使用手册.html](使用手册.html)。

## 关于本仓库

- **不含**打包产物（`报销审核智能体.exe`、`_internal/` 运行时、`报销审核_开箱即用.zip`、演示视频）。仓库只保留可复现的源码与资源；便携版请按需自行用 `build.py` + `requirements-build.txt` 构建。
- **无密钥泄露**：源码中不含任何真实 API Key；`tests/` 里的 `test-secret-DO-NOT-SAVE` 之类均为测试用假串，用于验证密钥不会被持久化。
- 第三方组件的许可与声明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) 与 `assets/licenses/`。

## 边界

本程序执行**财务预审**，不接入税务发票真伪查询，也不代替业务真实性核实、财务审批与签章。陌生版式、扫描不清或明细未识别完整时，请对照原票复核，不要直接确认尚未核对的空字段。
